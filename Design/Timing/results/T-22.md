## 🔩 Board translation (native +1 removed; MODEL §(a): board timers fire `deadline + δ`, δ ∈ (0.03, 1.05] ms)

- **Acceptance bar is identical on the board.** It is decided by integer timestamps (`timeout_at > timestamp`, `combo.c:228`), not by the timer:
  - gap ≤ 15: key 2's real time < `t+16` ≤ timer (`t_real + 16 + δ`) → key path always first → combo.
  - gap 16: key path (key at `t+16.x`) or timer path (`t+16+δ`) — sub-ms coin flip on the board, deterministic key-first on native; **both drop R16 → same output (A, C)**. Only the log line's origin/prefix differs.
  - gap 17: board timer fires at `t+16+δ` ≤ `t+17.05`, key at `[t+17, t+18)` → almost always timer first (as native); outcome same either way.
- **Engine-time timelines on the board:**
  - a: combo C↓ `t+15` (key-driven, no offset), C↑ `t+25+δ` (native `t+26`).
  - b: A↓ `t+16` (key-driven), A↑ + layer 1 ON `t+26+δ` (native `t+27`), C↓ `t+32+δ` (native `t+33`).
  - d: A↓ `t+16+δ` (native `t+17`), layer ON `t+26+2δ` (native `t+28`), OFF `t+126+3δ` (native `t+129`).
  - f: H↓ `t+30`, layer 3 ON `t+40+δ` (native `t+41`), I↓ `t+60+δ` (native `t+61`).
- **Not covered by native (hardware only):** debounce (+4–6 ms per press, gap survives ±1 ms) and the left-hand BLE 7.5 ms anchor grid; a physical 8–15 ms left-left gap can land at 16 (out) by phase (MODEL §(e), C6). The bar itself (≤ T−1) is exact; what reaches it is the *apparent* gap.

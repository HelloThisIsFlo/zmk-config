## 📜 Spec (CLAIMS.md, quoted)

Purpose: E-29 holds in this band; margin = 1 ms.

Model section exercised: MODEL (d) hack-ON band `11 ≤ Δ < dA` (k1 = 16 → dA = 16): "B's press empties A's set → A delivered at Δ, layer at Δ+10; B re-raised, fresh set (hack + own combos), timer accepted (not inside the handler) → B at Δ + max(11,k2). Margin max(11,k2) − 10 ≥ 1." Plus MODEL (b) R2 (key sharing nothing → captured then `cleanup()`), R3/R4 (fresh set for the re-raised key), R8 (`is_quick_tap` false because `T_B = now`).

- Key 1 = pos 0 `&ak 1 A` (0x04): candidates R16 `<0 2>` 16 ms + hack 11 ms → k1 = 16.
- Key 2 = pos 3 `&kp D` (0x07) on base, `&bk L` (0x0F) on akA (layer 1): hack-only → k2 = 0.
- Mock arithmetic (RIG headline): `t(A) = e0.ms + 1`, `t(D) = t(A) + e0.ms + 1` → Δ = e0.ms + 1. Spec's `PRESS(0,0,12)` → Δ = 13 ✓ ("D-key at t+13" is consistent with RIG).

## 🧭 Board translation (nRF52840, per MODEL §(a))

- **Remove the +1s.** Hack rung at `t+11+δ` (K_MSEC(11) from A's capture). Key-first flush is timer-free: A↓ at exactly `T_D` (= Δ). Layer ON at `T_D + 10 + δ₁` (K_MSEC(10) scheduled inside D's press handler), follower delivered at `T_D + 11 + δ₂` (K_MSEC(11) scheduled in the **same** handler, µs later).
- **Margin is robust here**, unlike the timer-driven band: both timers are armed from the same instant, so `elapsed()` is identical; `K_MSEC(10)` = 329 ticks (10.04 ms) and `K_MSEC(11)` = 362 ticks (11.05 ms) → layer leads the follower by ≈ 1.01 ms regardless of phase. MODEL (d)'s "nominal 1 ms margin … can be eaten by sub-ms phase" caveat applies to `Δ ≥ dA` (layer from A's timer-driven delivery vs B's own K_MSEC(11)), not to this band.
- Board timeline for Δ = 13: A↓ @13, A↑ + layer ON @23.0x, L↓ @24.0x, L↑ + layer OFF @34.1x. Add ≈ 4–6 ms debounce to both physical presses (equal for same-half keys → Δ unchanged); R1 has no split, so no BLE anchor shift — for a real cross-half pair read MODEL (d) "Cross-hand mapping".
- **Δ = 11 on the board:** the hack timer fires at `t+11.03`; D stamped `t+11` may be processed before or after it. After (≈ 97 % of the ms): timer line `remaining_candidates=1 timestamp=t+11` first, then D's key-path line and the flush. Before: as native (no timer line). Same delivery: A @11, layer @21, L @22 → HIT.
- **Δ = 16 on the board:** coin flip between ladder-first (R16 timer at `t+16.03` delivers A, D then arrives as a fresh first key) and key-first (as native). Same numbers: A @16, layer @26, L @27 → HIT. Nothing in this test depends on the outcome of that flip.
- No `CONFIG_ZMK_HID_SEPARATE_MOD_RELEASE_REPORT` in R1 (as CLAIMS); no modifiers involved, so report ordering is identical to the real firmware for this sequence.

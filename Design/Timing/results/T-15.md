## 🔌 Board translation (native +1 ms per timer removed; MODEL §(a))

- Hack flush: native **t+12** (`timestamp=t+11`) → board **t+11+δ**, δ ∈ (0.03, 1.05] ms. The hold-tap is created then.
- Term timer: scheduled as `(T+100) − k_uptime_get()` from that point → native fires at **t+101** → board **t+100+δ**. Created at t+11 on the board, it still decides at t+100; the hack's 11 ms is not added.
- Boundary on the board (integer-ms engine timestamps):
  - release stamped ≤ t+99 → TAP
  - release stamped **t+100** → the `:636` check (`ts > T+100`) is false. It is TAP if the release is processed before the sub-ms timer fire, HOLD if after → **coin flip on the board, TAP on native** (case b).
  - release stamped ≥ t+101 → HOLD, either by the timer or forced by `:636`.
- Queue tick: native Y↑ at **release+11** → board **release+10+δ**.
- Interrupt ordering (d, e, f) is **not** a timer artefact. `tap↓` → `release_captured_events` → `&kp` HID↓ run synchronously in one work-queue handler, so the board shows the same Y↓ D↓ Y↑ order. Only the Y↑ time shifts (−1 ms).
- On Flo's real board the linger keys sit in 16-ms combos (MODEL §(e)), not hack-only ones. The hold-tap is then created at t+16+δ instead of t+11+δ, and the decision time is unchanged (term counts from T).
- Transport (debounce, BLE for left-hand keys) shifts T itself, not the relative timeline.

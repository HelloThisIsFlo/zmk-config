Facts the spec does not state:
- **Δ = 112 is a same-ms tie, not a late arrival.** Both timers fire at t+129: the sticky release (armed at t+28 for 100 ms) and LB3's last combo rung (re-armed at t+124 for its t+128 deadline). The sticky runs first because it was armed first.
  - Zephyr `kernel/timeout.c:125-131` inserts a new timeout *after* existing ones with an equal deadline (strict `t->dticks > to->dticks`).
  - The work queue is FIFO, so the layer is off before LB3 resolves.
- **Consumption keeps the layer past its nominal end (E-60/E-61).** At Δ = 110 and 111 the layer does not go off at +129. It goes off on the follower's `&bk T` kp↑ (+138, +139).
  - The order in that ms is `hid_listener_keycode_released` → `mo_keymap_binding_released: position 0 layer 19` → `layer 19 state 0`.
- **The follower's key-up is dispatched on the layer it was pressed on.** At Δ = 110 and 111 the release reads `layer_id: 19 … flo,behavior-buffered-key`, although layer 19 was already off at +138/+139. This comes from the keymap's per-position layer snapshot. It is harmless: the `&bk` release branch has `count: 0`.
